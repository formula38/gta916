# Content Drop

Turns server milestones into channel-ready content. Playbooks live in
`channels/` (faceless-youtube, streaming, marketing-materials); strategy in
`docs/strategy/gta916-audience-and-income.md`. Data flows one way: the
server feeds the channels, never the reverse.

## Workflow

1. **Pick the story.** Source it from `CHANGELOG.md` or the current roadmap
   phase (`docs/strategy/gta916-roadmap-whitepaper.md`). Early-access
   Enhanced milestones are high-value: almost nobody else can make them.
2. **Pick the channel(s)** and produce the matching deliverable:

   **Faceless YouTube** - deliver: title (<60 chars, curiosity + specificity),
   hook script (first 15s), beat-by-beat outline, footage shot list the user
   can capture in-game, description with Discord CTA, tags.

   **Streaming** - deliver: stream title, segment rundown with timestamps,
   3+ clip-worthy moments to engineer, chat prompts, post-stream clip list
   for Shorts/TikTok repurposing.

   **Marketing materials** - deliver: asset brief for Higgsfield MCP
   generation (format, dimensions, copy, 916/Sacramento visual identity),
   where it gets used (Discord banner, server listing, thumbnail).

3. **Anchor everything in the 916 identity** - Sacramento references,
   locations, and community angles are the differentiator; generic GTA RP
   content is a commodity.
4. **Compliance check:** monetization mentions must match
   `docs/policy/monetization-readiness.md` (Tebex-only, no pay-to-win
   promises, no misleading claims).
5. Save deliverables under the matching `channels/<channel>/` folder and
   add a `CHANGELOG.md` entry.

## Cadence target (post-launch)

One in-game update + one content drop per week, each referencing the other:
the update is the video topic; the video announces the update.
